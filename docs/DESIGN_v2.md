# CaféPick v2 設計

> 狀態：草稿，待確認｜日期：2026-10-12

## 1. 一句話

打開手機，告訴它「我現在要幹嘛」，它從你附近挑 3 間最適合的咖啡廳，每間附一句理由。

## 2. 設計原則

1. **手機優先**：單手操作、拇指範圍內完成；桌機只是放大版。
2. **幫你決定，不是給你清單**：預設 3 間，不是 20 間。
3. **情境取代開關**：先選「要幹嘛」，細節條件收在第二層。
4. **誠實面對資料缺口**：不知道有沒有插座，就寫「未知」，不要假裝。

## 3. 使用情境（三個都要涵蓋）

用「情境」一次套好權重，使用者只要點一下：

| 情境 | 最在意 | 次要 | 不在意 |
|---|---|---|---|
| 💻 **工作／讀書** | 插座、WiFi、不限時、安靜 | 座位多、營業到晚 | 裝潢、甜點 |
| 💬 **約會／聊天** | 評價高、氣氛、可訂位 | 甜點、價位 | 插座、WiFi |
| ☕ **喝一杯就走** | 距離近、現在有開 | 評價、價格 | 其他全部 |

**🐶 帶毛孩（寵物友善）** 不是第四個情境，而是一顆可以和任何情境疊加的開關：帶狗去工作、帶狗去約會都很常見。打開後只推薦標示可帶寵物的店，卡片上顯示 🐶 標籤。

```
[ 💻 工作 ] [ 💬 約會 ] [ ☕ 喝一杯 ]
[ 🐶 帶毛孩 ]                          ← 情境下方一顆小開關
```

情境之外，保留一個「調整條件」抽屜給進階使用者（價格上限、走路幾分鐘內、必須有插座…）。

## 4. 手機使用流程

```
打開 App
  │
  ├─ 要求定位（拒絕 → 改選捷運站／行政區）
  ▼
[ 💻 工作 ] [ 💬 約會 ] [ ☕ 喝一杯 ]     ← 首頁就是三顆大按鈕
  │
  ▼
地圖（上半）＋ 底部抽屜（下半）
  ┌──────────────────────────────┐
  │ 1  Cafe de Gear      ★4.5   │
  │    走路 4 分・插座多・不限時   │  ← 一句理由
  │    [導航] [收藏]              │
  ├──────────────────────────────┤
  │ 2  ...                       │
  │ 3  ...                       │
  └──────────────────────────────┘
  │
  └─ 「都不喜歡？換 3 間」按鈕
```

重點：
- 從打開到看到推薦，**最多點 1 下**（有定位時）。
- 卡片往上滑展開詳情（營業時間、照片、所有標籤）。
- 「導航」直接開 Google Maps App。
- 收藏存在手機本機（localStorage），不需要登入。

## 5. 資料來源：兩邊一起用

| 資料 | 來源 | 說明 |
|---|---|---|
| 店家名單、位置、評分、評論數 | Google Places | 最新、最完整 |
| 現在有沒有開、營業時間 | Google Places | 「喝一杯」情境必備 |
| 價位、可訂位、適合團體、戶外座位 | Google Places | 約會情境用 |
| **可帶寵物** | Google Places（`allowsDogs` 欄位） | 帶毛孩開關用；Cafe Nomad 沒有這項資料 |
| **WiFi、插座、安靜、限時、座位** | **Cafe Nomad** | 工作情境的核心，Google 沒有 |
| 最近捷運站 | 內建靜態捷運站座標表 | 不再每間店打一次 API |

**怎麼把兩邊配對**：同一間店 = 店名相似 + 座標距離 < 80 公尺。配不到的店照樣推薦，但工作相關標籤顯示「未知」。

**Cafe Nomad 資料**：每天抓一次存進 SQLite，不要每次搜尋都去打它的 API。

## 6. 推薦演算法

每間店算 0–100 分：

```
分數 = Σ (該情境的權重 × 這間店在該項的分數)
```

- 每項分數都正規化到 0–1（例如：評分 4.5 → 0.9、走路 3 分鐘 → 0.95）。
- **資料缺漏給 0.5（中性）**，不是 0，避免沒在 Cafe Nomad 上的店被埋掉。
- 硬條件（例如「必須現在有開」、「走路 10 分內」）先篩掉，再排分數。
- **推薦理由** = 分數貢獻最大的 2–3 項，翻成白話：「走路 4 分・插座多・不限時」。

## 7. 技術架構調整

保留：React + Vite + Tailwind、FastAPI、Google Maps。

要改的：

| 項目 | 現況 | 改成 |
|---|---|---|
| 推薦邏輯 | 分散在 `recommend.py`（讀 DB）和 `routes/cafes.py`（打 Google），分數是 `None` | 統一一個 `ranker.py`：抓資料 → 合併 → 打分 → 產生理由 |
| 最近捷運站 | 每間店呼叫一次 Google API | 靜態捷運站 JSON，本地算距離（省錢、更快） |
| 版面 | 桌機左右分欄＋大型 Hero 區 | 手機：上地圖下抽屜；桌機：左清單右地圖 |
| 篩選 | 7 個開關平鋪 | 3 個情境按鈕 ＋ 收起來的進階條件 |
| repo 清理 | `frontend/.venv/`、`.DS_Store` 共 1908 個檔案被 commit | 移出版控、加進 `.gitignore` |

## 8. 分階段實作

| 階段 | 內容 | 完成標準 |
|---|---|---|
| **0. 能跑起來** | repo 清理、`.env.example`、確認 `run_dev.sh` 能啟動 | 你本機一行指令看到畫面 |
| **1. 資料合併** | Cafe Nomad 每日快取＋與 Google 配對、靜態捷運站表 | API 回傳的店同時有評分和插座資訊 |
| **2. 情境推薦** | `ranker.py`、三種情境權重、推薦理由 | 同一地點切換情境，結果明顯不同 |
| **3. 手機介面** | 情境首頁、地圖＋底部抽屜、導航、換一批 | 手機瀏覽器上單手可用 |
| **4. 收尾** | 收藏、讀取骨架畫面、錯誤提示、PWA（可加到主畫面） | 可以加到手機桌面當 App 用 |
